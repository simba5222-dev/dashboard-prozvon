# API Авито — конспект для интеграции (17.11.2026)

**Источник и оговорка.** Официальная документация (`avito.ru/developers`, `developers.avito.ru`) закрыта от серверов защитой
по IP (403/429 с капчей) — и с Амстердама, и с офиса, и даже `curl` с мака. Конспект собран по открытому зеркалу
официальных swagger-файлов: репозиторий `elchin92/avito-mcp`, папка `swaggers/` (18 разделов API). Это стороннее зеркало:
**каждый метод сверять с реальным ответом API**, когда появятся ключи. Сам API (`https://api.avito.ru`) с обоих серверов отвечает.

## Доступ
- Ключи берутся в кабинете Авито: «Для профессионалов → API». Выдаётся пара `client_id` + `client_secret` (на один профиль;
  если выпустить новый секрет, старый перестаёт работать).
- Получить токен: `POST https://api.avito.ru/token`, форма (`application/x-www-form-urlencoded`):
  `grant_type=client_credentials`, `client_id`, `client_secret` → `access_token` (живёт ~24 часа), дальше заголовок
  `Authorization: Bearer <токен>`.
- Две схемы: **client_credentials** — доступ к своему профилю (достаточно пары ключей, прав/scopes нет) и
  **authorization_code** — для сторонних приложений, нужны scopes (`messenger:read`, `messenger:write`, `stats:read`,
  `user:read`, `user_balance:read`, `items:info` и др.). Нужные нам разделы (звонки, мессенджер) поддерживают client_credentials.
- `user_id` профиля: `GET /core/v1/accounts/self`. 403 на методе обычно значит, что тариф/доступ не включает этот API.

## Разделы, которые нам нужны
### CallTracking (звонки по объявлениям) — только client_credentials
| Метод | Что делает |
|---|---|
| `POST /calltracking/v1/getCalls/` | звонки за период: `dateTimeFrom`, `dateTimeTo` (RFC3339, не больше 3 месяцев), `limit` ≤ 100, `offset` |
| `POST /calltracking/v1/getCallById/` | один звонок |
| `GET /calltracking/v1/getRecordByCallId/?callId=` | аудиозапись звонка |

Поля звонка: `callId`, `callTime`, `buyerPhone`, `sellerPhone`, `virtualPhone` (защитный номер Авито, через который шёл звонок),
`itemId` (объявление; проставляется не всегда), `talkDuration`, `waitingDuration`. Ошибка — объект `error{code,message}`.
**Зачем:** связать звонок с конкретным объявлением и сверить с нашими линиями «Авито СПБ» и т. п. в ВАТС.

### Мессенджер (чаты по объявлениям) — client_credentials или `messenger:read/write`
| Метод | Что делает |
|---|---|
| `GET /messenger/v2/accounts/{user_id}/chats` | список чатов (объявление, собеседник, последнее сообщение, `direction` in/out) |
| `GET /messenger/v2/accounts/{user_id}/chats/{chat_id}` | один чат |
| `GET /messenger/v3/accounts/{user_id}/chats/{chat_id}/messages/` | сообщения чата |
| `POST /messenger/v3/webhook` (`{"url": ...}`) | подписка на события; URL должен отвечать 200 за ≤ 2 с |
| `POST /messenger/v1/subscriptions`, `POST /messenger/v1/webhook/unsubscribe` | список подписок, отписка |
| `POST /messenger/v1/accounts/{user_id}/chats/{chat_id}/messages` | **отправка сообщения** (пишущий метод, только по слову владельца) |
| `POST .../chats/{chat_id}/read` | отметить прочитанным (пишущий) |

### Прочее (на потом)
`user`: баланс кошелька, история операций (`/core/v1/accounts/...`); `items`: объявления; `cpa`, `promotion`, `reviews`,
`tariffs`, `autoload` — статистика, продвижение, отзывы. Для расходов по рекламе — отдельный разбор после первых двух.

## Правила работы
1. Сначала **только чтение**. Отправка сообщений, отметка «прочитано», любые пишущие методы — только по отдельному слову владельца.
2. Токен кэшировать до истечения, не просить новый на каждый запрос; ключи — в `.env` дашборда (права 600), не в коде и не в журнале карты.
3. Повторы на 429 — с паузой; запись в нашу базу идемпотентна (`callId`, `chat_id`/`message_id` как ключи).
4. Вебхук принимаем на `https://72-56-25-105.nip.io/...` (сертификат есть); отвечать 200 сразу, разбирать в фоне.

## Что проверено на живых ключах (17.11.2026)
- Токен выдаётся (`expires_in` 86400); профиль «СК Техноресурс», `user_id` 91454443; баланс кошелька читается.
- `getCalls` отдаёт поля: `callId, callTime, buyerPhone, sellerPhone, virtualPhone, itemId, talkDuration, waitingDuration`;
  за 2 суток — 17 звонков, у всех есть `itemId` и разговор > 0 с (по-видимому, в журнал попадают только состоявшиеся звонки — проверить на истории).
- `sellerPhone` совпадает с нашей линией в ВАТС (пример: …9268 = «Авито СПБ», 9213909268).
- `GET /messenger/v2/accounts/{user_id}/chats` работает с client_credentials.
- **Лимит частоты:** `getCalls` возвращает 429 на 2–3-м запросе подряд. Клиент `app/avito.py` держит паузу 2 с и при 429 ждёт 30/60/120/180 с.
- Ключи хранятся в `.env` дашборда (`DASH_AVITO_*`), в коде и журнале карты их нет.

## Чаты (подключены 17.11.2026, только чтение)
- Список: `GET /messenger/v2/accounts/{user_id}/chats` (`chat_types=u2i`, `limit` ≤ 100, `offset` ≤ 1000: глубже ~1 100 чатов подряд не
  отдаёт — старые достаём по объявлениям через `item_ids`). Сообщения: `GET /messenger/v3/.../chats/{chat_id}/messages/`.
- Подписок на вебхуки на приложении нет (проверено). Вебхук не подключали: хватает почасового опроса.
- Телефона клиента Авито не отдаёт; клиенты пишут его в тексте сами (≈11% чатов) — по нему чат связывается с заявкой CRM.
- Сбои: сервер Авито иногда отвечает 500/504 (на отдельных чатах — стабильно). Клиент повторяет с паузой, для сообщений один повтор;
  «больной» чат пропускается, чтение продолжается.
- Таблицы: `avito_chats`, `avito_messages`; скрипт `scripts/avito_chats_sync.py` (`--full` — вся история, `--days N` — свежее);
  таймер `dashboard-avito-chats` раз в час. Скорость чтения ~0,8 с на чат.
- Первый разбор (2026): 1 406 чатов, в 1 004 клиент писал; менеджер не ответил в 49%; медиана первого ответа 125 мин; в течение 15 мин — 32%.
