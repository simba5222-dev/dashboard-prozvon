# Четыре потока звонков

Разделение предложено владельцем 30.09.2026. До этого все звонки обсуждались
как один поток, и мы путались: у каждого свой путь, свои правила и своя цена.

**Общее правило, решение владельца от 30.09.2026:** распознаём всё Яндексом,
**обработку звонков на питерском сервере не делаем**. Его работа — принять
вебхук ВАТС, скачать запись и отдать её в Амстердам. Разбор, правила и память
живут здесь.

Цифры — замер за 23–29.09.2026, в пересчёте на рабочий день.

---

## 1. Реклама — входящие на рекламные линии

**Алиас:** `реклама`

Звонки на номера из объявлений. ВАТС называет такую линию сама (`telnum_name`:
«Авито СПБ», «Бренд»), и личной она не бывает — значит это почти всегда новое
обращение за техникой. Исключение одно: спам и ошиблись номером.

| | |
|---|---|
| Сколько | 16 заявок за 02.10, около 6–7 разговоров в день |
| Запись | ВАТС → питерский сервер |
| Распознавание | Яндекс SpeechKit, `deferred-general` |
| Разбор | **YandexGPT Lite, прямо с питерского сервера** |
| Что в CRM | диалог в карточку звонка, комментарий в контакт, комментарий и поля заявки |
| Состояние | **работает**, разбор доходит до заявки за секунды |

Поток целиком в России. В Амстердам уходит один короткий вопрос — повод
звонка, потому что справочники линий и номеров живут здесь.

### Отбор: что отсекается и почему

До скачивания записи, то есть бесплатно:

| Проверка | Почему так |
|---|---|
| разговор был — `duration > 0` | статусу ВАТС не верим: на общий номер звонок идёт по очереди, и статус не взявшего трубку попадает в итоговую запись. Цена доверчивости — 612 входящих за двое суток, у 244 разговор шёл дольше полуминуты |
| дольше 10 секунд | решение владельца 29.09 |
| есть ссылка на запись | без неё разбирать нечего |
| линия в списке общих номеров | метку «с рекламы» из CRM **не спрашиваем**: её ставит автоматизация позже вебхука, отсюда 689 ложных отказов за двое суток |

### Как находится заявка

Прямой ссылки «звонок → заявка» в API нет: у карточки звонка связей нет вовсе,
у заявки их 22 и ни одной про звонок. Зато в заявке остаются следы того самого
звонка.

```
телефон клиента   custom-276     есть у 43 заявок из 50
линия             custom-278     есть у 44 из 50
время создания                   совпадает с началом разговора, −14…+1 с
```

Ищем в окне **минута назад, две вперёд** от начала звонка. Телефон совпал —
берём. Телефона в заявке нет, но совпала линия — берём вторым сортом. Телефон
есть и чужой — мимо, даже если линия та же. Осталось несколько — та, где
совпала линия и время ближе.

**Через контакт не ищем.** Решение владельца 02.10.2026: в CRM бывают дубли
контактов по одному номеру и заявки вовсе без контакта, а связь
«контакт ↔ заявка» появляется позже самой заявки — наблюдали отставание в
одиннадцать минут, и разбор уходил в никуда.

Не нашли — разбор кладётся на полку (`data/pending-orders` на питерском), и
догон `asr-fill-orders` раз в час пробует снова, трое суток. Разбор платный,
заново не считается.

**Что дальше:** разметка владельца на `/ads` → замер ошибок → правка задания
и базы знаний.

## 2. Входящие — на прямые номера менеджеров

**Алиас:** `входящие`

Клиент звонит менеджеру напрямую. Задача одна: не упустить запрос на технику,
о котором менеджер не сказал никому. Найденное становится заявкой
«Пойманная с прослушки».

| | |
|---|---|
| Сколько | ~305 в день, 282 минуты |
| Запись | питерский сервер → дашборд (`/vats-hook`), сразу после разговора |
| Распознавание | **только начало разговора**, Яндексом |
| Разбор | gpt-4o, просев «кто у кого спрашивает» |
| Что в CRM | заявка «Пойманная с прослушки», если находка подтверждена |
| Состояние | **работает**, 115 просеяно из 436 за 30.09 |

**Почему не целиком:** начала хватает, чтобы понять, есть ли запрос. Полная
расшифровка втрое дороже и на этот вопрос не отвечает лучше.

### Когда заявку НЕ заводим

| Случай | Решение владельца |
|---|---|
| Менеджер сам ищет технику у исполнителя | не заявка: спрашивает не клиент |
| Разговор по действующей заявке | не заявка |
| **Продление аренды, которая уже идёт** | **не заявка** — 02.10.2026 |
| Менеджер уже завёл заявку сам | не дублируем |
| У клиента открыта заявка на **ту же** технику | не заявка |
| У клиента открыта заявка на **другую** технику | **заявка есть** — 02.10.2026 |

Продление звучит как «ещё на день», «оставьте до пятницы», «по экскаватору
на завтра продление нужно». Отличается тем, что техника у клиента уже
работает, и менеджер отвечает «сделаем, пришлём» — не спрашивая, что за
объект и какая нужна машина: он и так знает.

**Что дальше:** понять, почему просеивается треть, а не всё. И голова в Яндекс.

## 3. Прозвон — исходящие по тёплым клиентам

**Алиас:** `прозвон`

Менеджер обзванивает тех, кто обращался раньше, и выясняет потребность.
Отдельный отдел, отдельный отчёт по каждому человеку.

| | |
|---|---|
| Сколько | единицы в день, номер один — 79214401135 |
| Запись | питерский сервер → дашборд |
| Распознавание | Яндексом |
| Разбор | `analyze_calls.py --group`, ежечасно таймером `dashboard-prozvon` |
| Что в CRM | заявка по итогу разговора, выжимка в карточку |
| Состояние | **работает**, но запускается пачкой раз в час |

**Что дальше:** голова в Яндекс.

## 4. Поиск техники — исходящие поставщикам

**Алиас:** `поиск`

Менеджер обзванивает исполнителей и спрашивает свободные машины. Правило
владельца: **это работа по уже созданной заявке, а не новое обращение**.
Заявки здесь не возникает никогда. Ценность — в том, что поставщик называет
своим сверх того, о чём спрашивали: такую технику надо завести ему в карточку.

| | |
|---|---|
| Сколько | разбирается 11–24 в день; всего исходящих ~164 |
| Запись | дашборд тянет по ssh с питерского, раз в минуту |
| Распознавание | Яндексом |
| Разбор | `analyze_search_calls.py`, ежечасно |
| Что в CRM | техника в карточку исполнителя, отметка «не занесено» |
| Состояние | **работает** на отделе поиска |
| Не писать | цену поставщика в поля заявки заказчика — это чужая ставка |

**Что дальше:** охват. Сейчас берутся звонки отдела поиска, а исходящих в
компании впятеро больше.

## Чего нет ни в одном потоке

**Голова всё ещё не Яндекс.** Решение владельца от 29.09.2026 — «уши Яндекс,
голова Яндекс с выделенной памятью». Уши переведены, голова осталась на
gpt-4o и gpt-4o-mini. Это общая работа для всех четырёх потоков.

**Инструкции для владельца** лежат у него на маке, в
`Документы/Рабоа в Клоде/`:

- `Команды по звонкам.html` — потоки и команды со слэшем;
- `Как работать с алиасами.html` — слова для терминала, все проекты разом.

**Меняя границы потоков, команды или алиасы, поправить и их** — иначе он
будет читать вчерашнее. В инструкции по алиасам перечислены все слова
поимённо, включая алиасы других проектов.

**Цены, замер на настоящих записях:** распознавание 0,48 ₽ за звонок (обе
дорожки), разбор YandexGPT Lite 0,26 ₽, gpt-4o 0,79 ₽.
